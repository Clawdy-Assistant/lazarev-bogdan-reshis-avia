Сервис создан для блока «Разработка» турнира «Решись»: вариант C и дополнительные задания. Пользователь выбирает направление, дату и цену билета, а приложение показывает ожидаемый спрос, продажи, остаток мест и вероятность заполнения самолёта.

## Возможности

| Возможность | Что получает пользователь |
| --- | --- |
| **Прогноз** | Ожидаемое число покупателей и продаж при выбранной цене |
| **Распределение спроса** | Девять квантилей и десять интервалов вероятности на графике |
| **Календарь рейсов** | Загрузка по дням и сравнение цен |
| **Демонстрация** | Пример расчёта на главной странице без регистрации |
| **Личный кабинет** | Регистрация с подтверждением почты, вход и защищённая сессия |
| **Адаптивный интерфейс** | Работа на телефоне и компьютере |

## Как считается прогноз

```text
желающие = 0.5_base_demand − price_sensitivity × (цена − base_price)
продажи  = min(места, max(0, желающие))
```

Формула применяется к девяти квантилям спроса; медиана графика соответствует показателю «хотят купить». Реализация находится в `design-system/src/forecast.ts`, тесты сверяют результат с данными 155 рейсов в `data/forecast.csv`.

## Локальный запуск

Понадобится Node.js 22 или новее и npm.

```bash
npm ci
npm run dev
```

Приложение откроется на `http://localhost:3000`. Для проверок:

```bash
npm test
npm run build
```

Без `DATABASE_URL` в режиме разработки используется временная база в памяти; без почтовых настроек код выводится в консоль сервера. Для подключения настоящей базы и отправки писем скопируйте шаблон и заполните переменные:

```bash
cp .env.example .env.local
```

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения к Neon PostgreSQL |
| `GMAIL_USER` | Адрес Gmail для отправки писем |
| `GMAIL_APP_PASSWORD` | Пароль приложения Google для SMTP |

Секреты хранятся в `.env.local` и не добавляются в Git. В production база и настройки почты обязательны для функций, которым они нужны.

После заполнения `DATABASE_URL` примените схему базы командой `npm run db:migrate`.

## Развёртывание

**Рабочий адрес:** [ddln.space](https://ddln.space) · **Платформа:** MWS Cloud Platform

```text
Пользователь → DNS REG.RU → VPS MWS → nginx / HTTPS → Next.js :3000
                                                        ├─ Neon PostgreSQL
                                                        └─ Gmail SMTP
```

Приложение запущено на Ubuntu как служба `reshis-avia` под systemd и слушает только `127.0.0.1:3000`. nginx принимает публичный HTTP/HTTPS и проксирует запросы приложению. Сертификат Let's Encrypt установлен через Certbot; для него настроено автоматическое продление. Домен `ddln.space` и `www.ddln.space` направлен на зарезервированный внешний IP VPS, DNS-зона управляется в REG.RU.

**Обновление сервера:**

1. Подготовьте отдельную директорию релиза, сохранив производственный `.env.local` вне Git, и перенесите в неё изменения.
2. Установите зависимости и выполните `npm test` и `npm run build` в директории релиза.
3. После успешных проверок обновите пути службы `reshis-avia` на новую директорию, выполните `systemctl daemon-reload` и перезапустите службу. Предыдущий релиз сохраните для отката.
4. Проверьте статус службы, HTTPS, `/api/v1/routes` и работу регистрации с письмом. Правила Firewall должны разрешать входящие TCP 80 и 443.

Развёртывание выполняется вручную: автоматический деплой при `git push` не настроен. Временные или прекращённые ресурсы MWS и зарезервированные IP следует отдельно проверять в биллинге.

## API

Ответы возвращаются в JSON; ошибки имеют вид `{ "error": { "code", "message" } }`.

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/v1/routes` | Открыт | Список направлений |
| `POST /api/v1/demo/forecast` | Открыт | Демонстрационный прогноз |
| `POST /api/v1/forecast` | После входа | Прогноз по направлению, дате и цене |
| `GET /api/v1/calendar?route=&price=` | После входа | Загрузка рейсов по дням |
| `POST /api/v1/auth/register` | Открыт | Регистрация и отправка кода |
| `POST /api/v1/auth/verify` | Открыт | Подтверждение кода и вход |
| `POST /api/v1/auth/resend` | Открыт | Повторная отправка кода |
| `POST /api/v1/auth/login` | Открыт | Вход |
| `POST /api/v1/auth/logout` | Открыт | Выход |
| `GET /api/v1/auth/me` | После входа | Текущий пользователь |

## Безопасность

Пароли хранятся в виде хешей scrypt с солью; токены сессий и коды — в виде хешей. Сессионная cookie использует `HttpOnly`, `Secure` в production и `SameSite=Lax`. Код одноразовый, действует 10 минут и допускает пять попыток. Вход ограничивается по числу попыток, запросы проверяются схемами Zod, а запросы, изменяющие данные, — по источнику.

# Решись Авиа

Сервис прогноза продаж авиабилетов. Кейс турнира «Решись», блок «Разработка», вариант C со всеми дополнениями.

Выбираете рейс и цену, сервер считает, сколько билетов купят, сколько мест останется и какой шанс заполнить самолёт. График показывает распределение спроса по девяти квантилям.

**Сайт:** https://reshis-avia.vercel.app

## Что реализовано

| Требование ТЗ | Как сделано |
| --- | --- |
| Вариант C: страница и backend | форма на TypeScript отправляет данные в API, расчёт идёт только на сервере |
| График распределения спроса | десять блоков по 10 % вероятности, медиана совпадает с числом «хотят купить», отмечено число мест |
| Регистрация | имя, фамилия, почта, пароль, подтверждение шестизначным кодом из письма |
| Авторизация | вход, сессия в защищённой куке, выход, закрытый доступ к расчёту |
| Хостинг | Vercel, база Neon (PostgreSQL) |

Дополнительно: лендинг с живым примером без регистрации, календарь с загрузкой рейсов, готовые цены, примерка цены ползунком, версия для телефона.

## Формула

```
желают = 0.5_base_demand − price_sensitivity × (цена − base_price)
купят  = min(seats, max(0, желают))
```

Для графика та же формула применяется к каждому из девяти квантилей. Код лежит в `design-system/src/forecast.ts`. Тесты сверяют его с `my_forecast.csv` на всех 155 рейсах.

## API

Все ответы в JSON, ошибки в виде `{ "error": { "code", "message" } }`.

| Метод и путь | Доступ | Что делает |
| --- | --- | --- |
| `GET /api/v1/routes` | открыт | список маршрутов |
| `POST /api/v1/forecast` | после входа | прогноз: `from`, `to`, `date`, `price` |
| `GET /api/v1/calendar?route=&price=` | после входа | загрузка рейсов по дням |
| `POST /api/v1/demo/forecast` | открыт | расчёт для примера на лендинге |
| `POST /api/v1/auth/register` | открыт | регистрация и отправка кода |
| `POST /api/v1/auth/verify` | открыт | подтверждение кода и вход |
| `POST /api/v1/auth/resend` | открыт | новый код |
| `POST /api/v1/auth/login` | открыт | вход |
| `POST /api/v1/auth/logout` | открыт | выход |
| `GET /api/v1/auth/me` | после входа | текущий пользователь |

## Безопасность

- Пароли хранятся как хеш scrypt с солью, токены сессий и коды только в виде хешей.
- Кука сессии `HttpOnly`, `Secure`, `SameSite=Lax`.
- Код из письма одноразовый, живёт 10 минут и допускает 5 попыток.
- После 5 неверных паролей вход блокируется на 15 минут, запросы ограничены по IP.
- Запросы, меняющие данные, принимаются только со своего сайта.
- Данные проверяются на сервере схемами zod.

## Запуск на своём компьютере

```bash
npm install
npm run dev
npm test
```

Без `DATABASE_URL` работает временная база в памяти, а код из письма печатается в консоль сервера. Для настоящей почты и базы заполните переменные из `.env.example`, затем выполните `npm run db:migrate`.
